🔀 LLM 스마트 라우터 데모

Bedrock GPT-6 · Claude 5.5에서 모델을 바꿀 때 생기는 손실(캐시 재작성, thinking·툴 맥락 유실)을 목업 Converse/Responses API로 보여주고, 라우팅이 고정 모델보다 실제로 나은지 냉정하게 비교해요. 실제 API는 호출하지 않아요.

브라우저에서 실제 소형 모델(Gemini Nano 또는 WebLLM)이 워크플로와 첫 요청을 읽고 티어를 골라요. 판단 비용은 Haiku/Luna 단가로 환산하고, JSON을 못 내면 규칙 판단으로 대체해요. 모델은 첫 사용 때 한 번 내려받아요.

workflow.steps의 minTier/risk/kind는 라우터가 보는 정보, tasks[].steps의 needs(이 티어 미만이면 도구 인자 누락)·refuseBelow(이 티어 미만이면 거절)는 목업 모델의 숨은 정답이에요.

      
      

    

  


  

    동작 규칙
    
    
      
  • 작업 시작 때 한 번 티어·effort를 정하고 작업 동안 고정해요. 워크플로 하한(minTier, 계획·고위험 단계는 effort ≥ medium) 아래로는 내려가지 않아요.
    • 
      
  • 캐시가 살아 있으면(Claude 5분, GPT 30분) 다음 작업에서도 하위 티어로 내리지 않아요. 프롬프트 캐시는 모델별이라 바꾸면 다시 써야 해요.
    • 
      
  • 도구 오류 2회 연속 또는 거절(content_filtered / refusal)이면 effort는 그대로 두고 한 단계 위 티어로 올려요. 이미 최상위면 effort를 high로 올려요.
    • 
      
  • Claude 5.5 가격은 Bedrock 모델 카드에 없어 Anthropic API 정가(입력 $0.1/$2/$4, 출력 $0.5/$10/$20)를 썼어요. Bedrock 실제 단가는 다를 수 있어요. 캐시 규칙·토큰 수(글자/3)도 단순화한 시뮬레이션이에요.
    • 
      
  • Claude는 더 낮은 티어로 내려가면 이전 thinking 블록이 버려져요(Bedrock model_binding_mismatch). 진행 중인 도구 루프에서 이게 생기면 직전 도구를 한 번 다시 호출한다고 가정했어요(↺). GPT의 reasoning item 이동 손실은 확인된 근거가 없어 캐시 손실만 반영했어요.
    • 
      
  • 비교 전략: '턴마다 라우팅'은 매 호출의 입력만 보고 다시 고르는 일반적인 요청 단위 라우터(도구 결과 턴은 쉬워 보여서 내려감), '임의 전환'은 모델·effort를 무작위로 바꿔요. 최저 고정은 결과를 미리 알고 고른 값이라 실제로는 달성하기 어려운 하한이에요.
